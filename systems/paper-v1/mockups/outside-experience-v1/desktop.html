Operator console — desktop

Target: Desktop · 1440×900 · State 1 of 3 · Status: review · Updated 2026-09-17

Intent

The first state on the machine that runs the session rather than attends it. Same job as the tablet browser — choose what to open — but the desktop is where you compare many sessions at once and see which devices are in each room.

Why it is built this way

  • This is the rulebook's one per-target exception: compact menu capsules at --hit-pointer and --row-pointer table rows, earned by pointer precision. A mouse resolves a target a gloved thumb cannot.
  • A table, not cards. On a desktop the task is scanning down a column, and cards make that harder, not easier.
  • The selected row is filled black, matching selection everywhere else in the language.
  • Numbers are tabular in the numeral face, so device counts and durations align down the column.

Open questions

  • Should the side panel preview a live session's view, or is that a second screen's job?
  • Does an operator ever need to join a room from here, or only host and observe?
