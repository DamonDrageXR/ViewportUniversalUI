Target: Desktop · 1440×900 · State 2 of 3 · Status: review · Updated 2026-09-17

Intent

The held state on the machine that prepares the session. The same rule applies — one edge-justified panel, view stays open — and the extra room a desktop has is spent on density rather than on a second panel.

Why it is built this way

  • One panel at 32%, under the 35% cap. The temptation on a desktop is a second panel on the other edge; the rule exists because that is how the view stops being the product.
  • The desktop allowance spent where it helps: a --hit-pointer layer tree, which puts twice the scene in view without scrolling.
  • Selection is a black fill in the tree, matching the console table and the tablet rail.
  • The view keeps its world-anchored tag, so what the operator sees matches what the person on site sees.

Open questions

  • Does the operator need to see each joined device's viewpoint here, or is that the observe screen?
  • Should the tree allow multi-select for bulk visibility, and if so what does selection-as-black-fill look like across many rows?
