How to use this repo

Design systems and the mockups built with them. Looking is free — open a file and it works. Editing needs the studio server, because that is what writes your changes to disk.

Just looking

  • Overview — every system and its mockups, read-only.
  • Style guide — the component library, rendered.

Double-clicking the files works. No install, no server.

Working on it

npm install     # once
npm run studio  # http://localhost:4173/studio/

The studio writes real files under systems/. Nothing lives in browser storage, so your work is in git and survives the machine.

Systems and versions

A system is a palette, a type scale, a spacing scale and a set of hit-target floors. Mockups live inside the system they were built with.

Both are named <family>-v<n>. New version copies forward and leaves the original untouched, so you can put v1 and v4 side by side. Nothing auto-versions, and nothing but Delete removes one — and that asks first.

Global settings cascade

A system is derived from about eleven values. Change one and everything below moves with it.

GlobalMoves
Accent colourThe accent ramp, the contrast-safe fill, focus rings, selection.
Neutral hue & saturationEvery surface, border and text colour.
Corner radiusAll four radius steps.
Spacing unitThe whole spacing scale.
Base text size & type scaleAll seven type steps.
DensityEvery hit-target floor. Field pushes them to 56/64/72px.
Panel opacityHow much of the 3D scene shows through a panel.

The colours that carry text are derived, not picked: the accent fill and accent text are computed by walking lightness until they clear 4.5:1 against the surface they actually sit on. Set the accent to anything — a sweep of 432 accent and theme combinations across the full hue circle stays above AA.

Editing by clicking

Open a mockup from the studio and press Inspect. Hover highlights; clicking shows which tokens that element actually resolves to, and gives you the right control for each.

What you clickedWhat you get
A colourA colour picker and a hex field.
A corner radius, size or spacingA slider and a number, with sane limits.
A fontA font picker.

Changes apply live and Save writes them to the system as overrides. An overridden token shows as custom in the editor with a reset link, so it is never a mystery why a global stopped affecting something.

Paging through

Every page except the overview has a sticky bar: ← Gallery and a Prev / Next pager through everything.

KeyDoes
← →Page back and forward.
EscBack to the overview.

Arrow keys are handed back to whatever is focused, so a slider still behaves normally.

Comparing across systems

Add ?system=<id> to any mockup URL and it renders with that system's tokens instead of its own — the way to check whether a palette change works on a real screen before committing to it.

Check it

npm run audit

Renders every page in both themes, once per system, composites translucent panel fills down the ancestor stack, and checks contrast against WCAG AA and every interactive element against --hit-min. Exits non-zero on failure.

The rules

Eleven of them, each with the reason it exists, in conventions.md. The short version:

  1. No raw colours or pixel values in a mockup — only tokens.
  2. Nothing interactive below --hit-min; --hit-xr for ray or field use.
  3. Panels are translucent; anything over the scene gets its own backing.
  4. State is an ARIA attribute, not a class.
  5. Written twice means it belongs in components.css, with a specimen.
  6. Every mockup states its intent and its open questions.
  7. Contrast is measured, not eyeballed.
  8. Never hand-edit a generated file.
  9. Versions are explicit, and never overwrite.
  10. Derive colours that carry text — do not pick them.
  11. Mockups are self-contained and build-free.
