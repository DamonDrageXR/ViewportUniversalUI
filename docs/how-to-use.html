How to use this repo

Everything here is plain HTML and CSS. There is no build step, no framework and nothing to install to look at a mockup.

Look at what exists

  • Gallery — every mockup in the repo.
  • System preview — the component library itself, rendered.

Double-clicking the files works. For a real origin, run npm run serve.

Make a new mockup

node tools/new-mockup.mjs "Desktop review — measurement panel" --device desktop

Devices: ipad-landscape, ipad-portrait, desktop, desktop-wide, headset, phone.

The review bar

Every mockup gets these four controls automatically:

ControlWhat it shows
Light themeThe same layout in the other theme. Both have to work.
8px gridWhether spacing is on the scale or just close to it.
Hit targetsOutlines every interactive element.
Fit to windowScales the frame without changing the layout inside it.

Paging through

Every page except the gallery has a sticky bar at the top: ← Gallery, and a Prev / Next pager through everything in the repo.

KeyDoes
← →Page back and forward.
EscBack to the gallery.

Arrow keys are handed back to whatever is focused, so a slider or a text field still behaves normally.

Check it

node tools/audit.mjs

Checks text contrast in both themes — with translucent panel fills composited properly, which is the part everyone gets wrong — and checks every interactive element against --hit-min. Exits non-zero on failure.

The rules

Eight of them, each with the reason it exists, in conventions.md. The short version:

  1. No raw colours or pixel values in a mockup — only tokens.
  2. Nothing interactive below --hit-min (44px), --hit-xr (64px) for ray or field use.
  3. Panels are translucent; anything floating over the scene gets its own backing.
  4. State is an ARIA attribute, not a class.
  5. Written twice means it belongs in components.css, with a specimen.
  6. Every mockup states its intent and its open questions.
  7. Contrast is measured, not eyeballed.
  8. Mockups are self-contained and build-free.
